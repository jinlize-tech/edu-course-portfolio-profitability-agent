# JLZ-EDU-AG-027 Codex执行任务书

## 1. 基线

- 任务编号：`JLZ-EDU-EXPANSION-30-FULL-DELIVERY`
- 候选来源：`CAND-033`
- 正式产品：`JLZ-EDU-AG-027` / 课程产品组合盈利诊断
- 类型：Agent
- 批次：1
- 业务中心：12 经营决策与财务规划中心
- 版本基线：`EDUCATION_BASELINE_V1.0.0`
- 产品版本：`1.0.0`
- 许可证：Apache-2.0

## 2. 用户、痛点与目标

- 用户：校长、产品负责人、财务负责人、多校区经营管理者
- 痛点：课程越多不代表越赚钱，低毛利、低满班、复杂教师依赖和高退费的课程可能长期拖累组织。
- 目标：按课程、班型、校区和客群分析收入、贡献毛利、续费、退费、复杂度和资源占用，制定保留/改造/退出路线。

## 3. 输入契约

| 键 | 名称 | 类型 | 必填 |
|---|---|---|---|
| `course_financials` | 课程财务数据 | array | 是 |
| `course_operations` | 课程运营数据 | array | 是 |
| `student_placement_constraints` | 在读学生安置约束 | array | 是 |
| `strategic_priorities` | 战略优先级 | array | 否 |
| `decision_weights` | 决策权重 | object | 是 |

## 4. 工作流

1. 统一课程编码
2. 建立盈利视图
3. 分群分析
4. 识别现金牛/问题课
5. 设计组合情景
6. 制定退出/改造计划
7. 设监控指标

## 5. 阶段状态

| 阶段 | 动作 | 退出成果 |
|---|---|---|
| S1_SCOPE_CONFIRMATION | 确认目标、校区/岗位/课程范围、期限、交付格式和可用资料。 | 任务确认单与最多3个关键缺口 |
| S2_EVIDENCE_INVENTORY | 盘点课程清单、收入与成本、班型、满班率、教师占用、续费、退费、招生周期、战略目标，标记来源、版本、敏感字段与冲突。 | 证据清单、缺口表和冲突表 |
| S3_PROFESSIONAL_DIAGNOSIS | 围绕按课程、班型、校区和客群分析收入、贡献毛利、续费、退费、复杂度和资源占用，制定保留/改造/退出路线。进行专业诊断，形成问题树和优先级。 | 问题树、风险和优先级 |
| S4_SOLUTION_DESIGN | 按统一课程编码 → 建立盈利视图 → 分群分析 → 识别现金牛/问题课 → 设计组合情景 → 制定退出/改造计划 → 设监控指标设计首选方案和受限备选方案。 | 方案、责任人、完成标准 |
| S5_HUMAN_CONFIRMATION | 由业务负责人复核输入事实、关键假设和最终成果适用范围。 | 确认记录、未决项和升级项 |
| S6_FINAL_DELIVERY | 生成完整交付成果，执行结构、证据、安全、品牌和独立安装检查。 | 最终成果、范围限制和复盘指标 |

## 6. 核心成果

- `课程组合矩阵`
- `盈利排名`
- `保留/改造/退出建议`

## 7. 差异化与排重

- 与现有产品：财务经营分析看总体趋势；班级成本分摊算单班；本产品跨课程组合做产品决策和退出编排。
- 排重检查：部分重叠；共享成本与收入，但输出课程组合决策与实施路线，不提供综合财务分析。
- 独立理由：只需课程级聚合数据即可独立诊断。

## 8. 安全与人工门禁

- 复核角色：业务负责人
- 复核范围：输入事实、关键假设和最终成果适用范围
- 不调用外部收费API。
- 不自动修改外部系统、执行退款、审批合同、处分员工或联系外部人员。
- 高风险产品完成状态必须确认人工复核。
